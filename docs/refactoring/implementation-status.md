# 重构实施状态

## 第一阶段：纯 Java 授权核心

已建立 `sparrow-platform` 聚合入口及 security-api、rbac-core、data-policy-core 三个新模块。无旧模块运行时依赖，无兼容转发类。

实现了资源/scope 注册、角色授权、拒绝优先与资格来源；行/字段策略保留各自行条件；业务行约束只能进一步收窄。授权数据和身份均以不可变快照传入。

已执行 `mvn -o -f sparrow-platform/pom.xml test`，88 个用例全部通过。最初采用 JUnit 5.11.4，离线运行因缺少 launcher 失败；调整为本机缓存完整的 5.10.3 后成功。没有修改旧依赖版本，也没有向目录外安装依赖。

验证覆盖 81 种功能/行授权组合及相反规则顺序，并测试逐行字段隔离、拒绝优先、无授权缺省拒绝、业务追加约束、用户/群组主体、作用域不匹配、空值与非法输入。

## 第二阶段：JPA 查询与受控更新

新增 data-policy-jpa，通过 Specification/Criteria 编译权限表达式，权限过滤先于分页和计数；返回逐行裁剪的值映射，避免返回完整受管实体。隐含字段不能用于任意筛选/排序。增加结构化 OR/NOT/IN 与字段追加限制。

受控 patch 要求事务和 update scope，检查可写字段、旧记录/新状态、业务 guard 和版本；所有授权检查先于实体变更。当前适配器只支持显式注册的标量字段和单主键，不支持的关联/类型明确失败。

H2 真实数据库集成测试覆盖分页计数、混合行字段隔离、SQL/内存空值一致性、敏感字段过滤拒绝、范围转移拒绝、过期版本、业务冻结与事务回滚。完整 reactor 共 97 个测试通过（88 核心 + 9 JPA）。H2 不替代生产数据库方言验收。

## 第三阶段：本地身份与可选装配

新增 identity-api、identity-local、identity-local-spring-boot-starter。默认使用 Spring Security DaoAuthenticationProvider/PasswordEncoder 和 JPA 账号存储；主体稳定 ID 与用户名分离，管理操作要求宿主提供管理授权 guard，密码专用命令与资料修改分离。

已验证真实数据库登录、密码哈希、启停、重置、旧会话失效、命名空间隔离、版本冲突、provider 缺失/重复；HTTP 测试覆盖会话登录和凭据重置后的 401。外部 provider 模式不装配本地数据库/登录链，无实现时启动失败。

完整 reactor 108 个测试通过（新增 8 个本地身份、3 个 Spring/HTTP 装配测试）。角色 provider、管理 REST/UI、登录失败限制、生产迁移脚本和外部认证桥接仍在后续阶段，不能仅凭这些测试视为完整身份交付。

## 第四阶段：角色、策略发布和群组持久化

新增 rbac-jpa、group-core/jpa。角色和角色分配通过 Criteria 读写，当前数据库关系决定有效角色，不信任会话的旧角色快照；用户/群组授予、角色停用、显式拒绝和 scope 来源分别验证。角色管理 SPI 可由项目替换；外部角色管理完整装配仍待后续。

数据策略增加草稿/发布/撤销、版本冲突、命名空间、显式 JSON AST 编解码及发布时 JPA 字段/类型校验。无发布规则时无数据许可。群组采用不可变图与命名空间事务锁，支持成员/嵌套/停用、环检测和全量变更前后委派检查。

完整 reactor 126 个测试通过：新增 6 个角色、5 个策略生命周期、4 个群组图、3 个群组数据库用例。群组当前采用有容量上限的命名空间快照，尚未进行大规模组织性能评估；管理 guard 必须由宿主接入真实授权，测试中的允许 guard 不是生产默认值。

## 第五阶段：页面能力、字典与本地文件

system 提供页面元素决策与可选字典服务。元素支持能力派生/显式限制、父子状态、逐行上下文和只读字段；呈现许可不能覆盖业务拒绝。字典编码稳定，停用项历史可读，删除依赖显式引用检查。

新增 storage-api/local 和 file-service。存储使用不透明 UUID 键、流式限额与 SHA-256，拒绝路径穿越/软链接。文件服务在授权 guard 后访问对象，上传回滚清理对象，删除采用 pending 状态与幂等重试。业务父对象和引用检查由宿主提供，失败清理的存储孤儿仍需要运维对账任务。

完整 reactor 141 个测试通过。尚未完成的管理 API/UI、文件授权管理、配置/导航持久化、生产迁移等仍需继续实施；当前文件列表只适用于明确授权整个命名空间的管理能力，普通行级文件列表需走受控查询适配器。

## 第六阶段：管理 HTTP 适配器与方法授权

新增 security-spring 和 web。方法权限切面在执行业务前检查资源/scope；管理 API 覆盖用户、角色/成员/功能授权、策略草稿/发布/撤销、群组、字典和文件，并提供当前会话功能及 CSRF token。角色 API 使用三个可替换 SPI，不直接依赖本地 JPA 角色服务；本地实现新增 RolePermissionManager 接口。

管理 HTTP 默认关闭，显式启用后仅注册已有服务对应的端点。可选业务依赖不会强制传递给宿主。测试通过过滤类加载器验证未安装数据权限、群组、文件、字典、角色和 Hibernate 时，身份管理接口仍可装配。宿主负责可信主体、认证过滤链和服务 guard，适配器没有默认放行授权。

完整 reactor 已执行离线测试，155 个用例通过，零失败/错误。新增 14 个用例覆盖方法拒绝不执行业务、外部角色分配及精确 scope、只读身份提供方、内部错误信息隔离、版本冲突、非法 JSON、可选模块装配与会话能力/CSRF 返回。完整 UI、独立管理服务器、生产数据库迁移及此前列出的生命周期完善仍未完成；本阶段不能视为整体重构验收。

## 第七阶段：独立管理宿主、页面与文件引用

新增 sparrow-admin-server，实际装配本地身份、当前角色/群组事实、管理 guard、策略、字典和文件服务。管理员引导只允许非 Web 进程，在事务内检查空账号命名空间；没有默认密码或用户名管理员特例。正常启动使用 schema validate，已经验证打包 JAR 的空开发库初始化与正常启动。

管理页面接入用户资料/启停/密码、角色成员/功能授权、群组成员/嵌套、策略草稿发布、字典条目和文件操作。页面使用当前功能权限、CSRF 与版本控制；目前策略编辑为 JSON，后续仍需补齐结构化规则表单。文件附件引用服务采用 Criteria 查询，与删除共享文件行锁，有引用不可删除、待删不可新增引用。

H2 与真实 Spring Security HTTP 集成覆盖匿名/普通用户拒绝、管理员操作、缺失 CSRF、版本冲突、会话内撤权、密码重置失效、策略保存/发布和静态资源保护。完整 reactor 共 163 个测试通过。原测试环境的 Mockito inline 动态附加失败，沙箱外重跑通过；本宿主测试不使用 final mock，已选用 subclass mock maker 以移除后续动态附加要求。

## 第八阶段：登录限制与事务审计

本地认证新增数据库共享的失败计数与限时锁定，默认 5 次失败后锁定 15 分钟，可配置 `sparrow.identity.login.max-failures` 与 `lock-millis`。正确密码不能绕过锁定，认证管理器不回退到无失败限制的父提供方；密码重置清除锁定，成功登录在数据库中复核凭据版本。登录锁定限制新登录，不主动踢出已合法建立的会话；停用/凭据重置仍使旧会话失效。

管理写操作通过宿主切面在同一事务内写业务数据与成功审计；审计写入失败则回滚业务。失败/拒绝尝试在独立事务记录。审计只接收主体 ID、HTTP 方法、路径、时间和结果，不接收请求体、密码或响应内容，提供受保护查询 API 和管理页面。认证过滤器之前的拒绝（例如 CSRF）尚不属于此应用层审计范围。

完整 reactor 168 个测试通过，新增验证共享锁定/到期、凭据并发重置、无认证回退、审计凭据隔离和审计失败导致业务回滚。第七阶段提交为 94eb4be，未推送。

## 第九阶段：文件范围执行、页面配置和系统管理

新增可选 file-policy 模块，基础 file-service 不依赖数据策略。业务 `/api/files` 使用当前功能资格、已发布行/字段规则、命名空间与追加业务约束；权限过滤与 READY 状态在分页/计数前执行，隐藏字段不返回，下载逐次检查，重命名检查旧值与新值。独立宿主在缺少父对象适配器时排除所有已绑定附件，不接受客户端父对象声明放行。文件策略预览使用真实主体与记录，只返回决策及字段许可，不返回记录值。

用户 provider 增加操作能力声明；角色授权及成员支持查询和撤销页面。页面定义/呈现规则有持久化、版本检查与独立能力接口，当前角色事实用于 ROLE 呈现规则；父级、公开/受限、字段与记录上下文仍不能覆盖业务拒绝。管理端提供规则输入及 JSON 高级编辑，前端适配器控制隐藏/禁用/只读，并防止异步旧许可覆盖新拒绝。

新增注册类型的配置管理与导航管理。配置保留 decimal 精度、仅显式公开项下发客户端；导航有父级限制、环检测、站内地址限制及版本控制。管理宿主已实际使用可配置标题和授权后的业务导航。

完整 reactor 181 个测试通过，前端能力适配器 4 个 Node 测试通过。覆盖实际 HTTP 的文件行/字段裁剪、下载越权、改名越界、附件追加约束、策略预览、READY 状态计数、页面规则与角色事实、配置权限，以及数据库级导航/配置校验。浏览器视觉验收仍受连接不可用限制。

尚需完成树结构替代、剩余装配与扩展契约检查、源码归属清单及最终交付文档核对；历史数据库迁移按用户要求不在本轮范围。

## 第十阶段：TREE / DAG 层级替代与架构约束

新增 tree-jpa 的不可变图、层级/节点/边实体和事务服务。通过层级行锁与 revision 保证并发操作校验，明确 detach、move、单节点删除与子树删除语义；DAG 存在集合外入边时拒绝子树删除。节点可绑定业务对象但不要求业务实体继承树基类，删除必须通过业务引用检查。
