## 3. 数据库迁移设计

### 3.1 预检与清单规则

- [ ] 导出实际 schema、数据库版本、命名策略结果、数据量、字符集/排序规则、约束和索引。
- [ ] 记录 JSON/TEXT/LOB 的真实类型和读取方式；若包含大对象引用，迁移内容并保留可验证引用，不把 OID 当文本复制。
- [ ] 扫描空主键、重复业务键、孤儿外键、未知枚举/判别值、无效 JSON、树环和共享后代。
- [ ] 检查 `spr_model.id` 与授权引用列长度差异：源码分别有 500 与 50 的声明，实际数据以数据库为准。
- [ ] 建立不可变备份、演练副本和迁移批次 ID；脚本记录版本、checksum、输入快照标识、开始结束时间及校验结果。
- [ ] 转换映射要求完整覆盖，未知项、冲突项阻断执行；禁止 skip、默认映射或静默删除。
- [ ] 若多旧值映射同一新值，必须有明确合并规则和冲突报告；数量核对不能简单要求每张表行数相等。

### 3.2 转换工作表

旧物理名称仅在源码显式声明时使用；隐式列/集合表名称需由 schema 导出补齐。目标名称均为设计名称。

| 对象 | 当前来源 | 目标转换 | 必须校验 |
| --- | --- | --- | --- |
| 模型及字段 | spr_model、spr_model_attribute | 类名 → resourceCode；字段名 → 显式 fieldCode；Java 类型 → 受控字段类型 | 映射覆盖、唯一性、所有引用闭合 |
| 用户/角色模型权限 | spr_user_model、spr_sysrole_model 及属性权限表 | 拆为 RBAC 的 resource+scope 授权和可选的行/字段策略；主体、效果、范围完整保留 | 按主体授权矩阵，不以旧查询结果作为唯一基线 |
| scope/菜单/页面授权 | Scope、*Scope、*Menu、*PageElement 的实际表 | scope → resource+action；菜单/元素 → 可见性或实例规则 | 不把菜单可见升级为业务操作许可 |
| 页面交互 | spr_page_element、spr_user_page_element、spr_sysrole_page_element 及前端绑定 | 稳定 pageCode/elementCode、能力绑定、DERIVED/RESTRICTED 模式和 UI 呈现策略 | 旧 ALLOW/DENY 的原展示用途逐项核对，不自动授予业务 scope；行上下文和字段读写规则完整 |
| 本地账号/凭据 | 实际用户来源与旧账号表（若存在） | 稳定主体 ID、规范化登录名、状态、哈希编码标识及 credentialVersion | 不猜测旧哈希算法；可验证且支持的哈希才迁入，无法安全转换时强制重置；外部主体不自动生成本地密码 |
| 角色 | Sysrole、UserSysrole、SysroleRelation | 按所选角色 provider 迁移 Role/RoleAssignment/RoleRelation 及稳定角色引用，保留来源 | 旧用户名到稳定主体 ID、角色重名及继承无环 |
| 群组 | spr_group、spr_group_entity 及 USER/SYSROLE/GROUP 判别值 | Group/GroupMembership/GroupNesting；角色分配迁入 RBAC，纯角色集合显式展开或归档 | businessId 按判别类型解析；不得推断旧 GroupSysrole 就是给用户组授予角色；核对真实用途、嵌套方向、主体来源、重复/孤儿/环及 owner/isRoot 语义 |
| 树 V1 | 各 BaseTree 子类表的 parentId/seq | 每个业务层级建 Hierarchy；节点绑定业务 ID，父关系转 Edge | 根集合、父子关系、路径、顺序、业务绑定一致 |
| 树 V2 | 各 BaseTreeV2 子类及 parentIds 集合表 | 每个父关系生成 Edge，保留对应 seq | 多父关系数量、共享后代、无环、无跨层级关联 |
| 字典 | spr_dict、spr_simple_dict、entityType 及目录集合/子类列 | 按已使用功能迁为 DictionaryDefinition/Entry；仅分级字典迁移目录关系；无独立字典模块 | 判别值全覆盖、子类字段无丢失、条目编码稳定、组合唯一、历史停用项可读、业务引用完整 |
| 配置 | spr_app_config、spr_config_item、dtype、valueType、valueStr | 显式配置类型和序列化值；自定义类型单独 converter | null/空串/数字/布尔语义、精度、附件关系、解析失败零项 |
| 视图与 JSON | spr_view_config、configJson/formJson、页面配置 | 按已知 JSON schema 迁移资源/字段/投影引用 | 禁止全库字符串替换；非引用文字保持原样 |
| 文件与附件 | BaseFile 子类、SprFile、附件及目录集合表 | FileMetadata + AttachmentReference；stable providerCode + locator | 文件 ID、对象存在性、长度/hash、排序和关联 |
| 审计/状态/锁 | 继承到每张业务表的字段 | 显式审计与业务状态映射；version 初始值 | 时间/时区、操作者、状态和值域一致 |
| 数据权限 token | dataPermissionTokenId 及外部引用 | 明确策略关联或批准后的归档删除 | 未识别引用为阻断项，不能置空跳过 |
| 衍生数据 | 缓存、索引、搜索文档、消息 | 清理/重建或离线转码后消费 | 旧序列化类名不再进入新运行时 |

### 3.3 授权语义迁移

动作映射采用显式表：READER→read、AUTHOR→create、EDITOR→update、DELETER→delete，DOWNLOAD/EXECUTE 等映射到明确动作。此表是设计起点，必须通过调用点确认实际含义。

- ALL_CRUD 展开为确认后的 read/create/update/delete；ALL、SHARE_ALL 等按迁移时的资源动作集合生成明确规则，不能意外授权未来新增动作。
- SHARE_* 不自动等同于目标动作许可；需要确认它表达“可转授”还是“共享后拥有”，映射失败即阻断。
- 旧系统未配置即放行的 scope，逐项标记为显式公开、指定主体允许或默认拒绝；不能批量生成全员授权来掩盖缺失。
- 旧管理员字符串特例迁为显式主体授权；去掉所有常量指向 SUPER_SYSADMIN 的隐式处理。
- 新系统 DENY 优先。对每个冲突记录列出旧存储规则、新预期结果和处理依据。
- 迁移时保留字段策略与原行条件、角色与功能 scope 的关联，禁止先合并行再合并字段造成权限扩大。
- 保存来源到新规则的映射及“同一主体/资源/动作”的前后决策差异。预期权限收紧也要列出，避免上线后才发现工作流中断。

### 3.4 转换顺序与执行边界

1. 在停写快照上完成预检，固定所有映射清单和版本。
2. 创建新表/列及迁移工作区；不启用新应用，不运行旧库自动同步模型任务。
3. 迁移主体、资源、字段定义和基础业务对象，保留可保留的主键。
4. 迁移授权、层级边、字典分类、文件关联等依赖关系。
5. 转换 JSON、类型编码、外部配置；初始化 version，补充显式约束及索引。
6. 按核对清单验证，再清理旧结构或移至不被新应用访问的离线归档；最终在线 schema 仅保留目标结构。
7. 写入成功的 schema 版本记录，应用使用 validate 启动，执行验收后开放写入。

迁移工具使用工作区映射表和检查点支持受控重试；版本脚本执行一次，失败不得通过删除版本记录盲目重跑。大数据量分批执行时，checkpoint 必须与该批数据在同一事务提交。无事务 DDL 的数据库需要逐步补偿与恢复预案。

按宿主选定的模块组合安装/迁移 schema；未启用的数据权限能力不创建其表，历史数据归档去向仍需登记。新库安装单独验证该组合的完整目标 schema。不得在空库执行依赖历史表存在的数据迁移；安装路径与升级路径最后应生成等价结构。

## 5. 数据与功能验收

| 类别 | 验收要求 |
| --- | --- |
| 数据数量 | 每张源表记录目标去向，拆分/合并/归档数量可解释；无未归属记录 |
| 关键业务字段 | 分批计算规范化字段校验和，关键对象逐字段核对；复杂值规范化规则固定 |
| 引用完整性 | 外键无孤儿；复合键全部组成部分已映射；JSON 中声明的引用可解析 |
| 权限 | 匿名、普通用户、角色、分组、系统主体、显式拒绝、未配置、越权字段和数据范围矩阵通过 |
| 群组 | 直接/间接成员方向、重复路径、停用中间组、并发成环、角色来源、命名空间隔离、外部事实不可用/过期、删除拒绝规则导致的权限扩大和管理员自我提权测试通过 |
| 权限组合 | 同行不同字段、跨角色 scope 来源、角色继承、拒绝优先、追加限制无法放权均有测试 |
| 可选模块 | 仅 RBAC、RBAC+Data Policy、业务追加约束三套装配通过；声明 FRAMEWORK 缺执行器时启动失败 |
| 字段与关联 | 隐藏字段与 null 区分，筛选/排序/聚合不泄漏；关联对象授权完整；不支持的规则明确失败 |
| 授权生命周期 | 策略发布及委派边界、撤权时限、缓存隔离、长任务逐批检查和安全审计可验证 |
| 页面交互 | 加载失败无闪现/误启用；同行字段与行按钮分别授权；父子限制、混合批量选择、键盘/快捷键禁用、只读字段提交语义、撤权刷新及绕过 UI 直接请求测试通过 |
| 查询 | 类型错误、语法错误、未知字段、继承字段、关联、分页计数和投影结果测试通过 |
| 写入 | 不存在更新失败；无隐式 insert；null patch、唯一冲突、乐观锁及整批回滚符合契约 |
| 层级 | 根集合、节点/边、路径和排序一致；环、共享节点、并发移动与删除边界通过 |
| 配置/字典 | 已启用功能的判别值和自定义属性不丢失；配置值语义保持；字典停用项可读、被引用项不可删；无反射类型加载 |
| 字典可选性 | security/rbac/data-policy 不依赖字典；无字典的宿主可独立启动和迁移，已有字典的宿主必须完成字典数据核对后切换 |
| 文件 | 元数据数量和附件关系核对；对象存在性清单；按约定校验内容 hash/长度，无法校验项须处理 |
| 性能 | 以演练前确定的阈值核对响应时间、查询数、批量内存及迁移耗时 |
| 管理闭环 | 用户管理框架及本地用户/角色实现用真实数据库和登录流程验证，外部替换用测试 provider 验证；角色/授权、策略、群组、文件/文件权限、字典及其他已启用内置功能完成页面/API 流程、越权拒绝、版本冲突、审计及失败重试 |
| 文件授权 | 功能资格与文件范围、附件父对象约束、直接 API/下载访问、授予/撤销有效期及凭据不泄漏测试通过 |
| 用户与角色 provider | SPI 无厂商类型，本地账号/角色管理真实可用，用户及角色 provider 独立可配；外部模式不回退/双写本地；Keycloak 真实集成后续单独验收 |
| 本地认证 | Spring Security 登录/退出、哈希验证、失败限制、启停/密码重置失效、CSRF/会话安全、跨节点状态校验和管理员引导通过 |
| 数据访问规范 | 动态条件优先 Specification/Criteria API；无未经说明的运行时 native SQL；必要例外有方言测试、参数绑定及授权覆盖，迁移 SQL 独立审查 |
| 架构 | 无环依赖；core/storage-api 不引入 Spring/JPA；没有重复完整类名或跨模块内部包调用 |
| 清理 | 生产代码无旧包、类名参数、旧路由和兼容开关；离线迁移数据可保留历史名称 |

## 7. 失败与恢复

写入开放前：停止新系统，恢复迁移前的完整数据库备份及匹配的旧应用/前端/配置；恢复对象存储或其他外部状态的变更清单。不能仅回滚 JAR，也不能让旧系统连接新 schema。

写入开放后：先停止所有写入并保全新数据，优先修复前进。若必须恢复旧版，先导出切换后的增量并制定数据回放/人工处理方案，再执行批准的恢复；禁止无视新产生的数据直接覆盖数据库。不可逆对象删除在验收完成前不执行，防止恢复后数据库引用已消失的对象。

恢复旧版本属于部署级灾难恢复，不要求新版本包含任何旧版适配代码。
