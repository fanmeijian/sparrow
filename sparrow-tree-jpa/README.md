# 层级结构

`HierarchyService` 保存层级、节点、边，业务实体通过 `resource + recordId` 绑定到节点，无需继承树实体。可选择 TREE 或 DAG；根由没有入边表示，根排序属于节点，其余排序属于边。

所有变更要求事务及当前 revision，在层级行锁内完成图校验和持久化。TREE 拒绝多父，所有模式拒绝环、自引用、跨层级边、重复边；图有 10,000 节点、50,000 边、64 层容量上限。排序保留最多 28 位精度和 8 位小数。

- `detach` 只解除一条关系。
- `move` 在一次事务中解除旧关系并建立新关系，移到根时必须已无其他父关系。
- `deleteNode` 拒绝仍有边的节点。
- `deleteSubtree` 是独立命令；DAG 集合内任一节点有集合外入边时拒绝，TREE 可删除一个完整子树。
- 删除节点还必须通过宿主的业务引用检查；管理 guard 可以检查变更前后的完整图。

宿主必须提供真实授权和业务引用适配器。独立管理服务器只允许管理不绑定业务对象的层级；未安装绑定适配器时不会猜测业务引用或放行删除。

测试覆盖不可变图语义、真实数据库版本/引用检查、并发反向关联、跨层级和命名空间隔离，以及管理 HTTP 越权拒绝。
